# Translations

Source of truth: `i18n/<locale>/<area>.json`. Everything under
`public/_locales/` and `lib/i18n/messages.generated.ts` is GENERATED by
`pnpm i18n:build` and checked by `pnpm i18n:check` (part of `pnpm lint`
and `pnpm build`). Edit the fragments, never the generated files.

## Runtime

```ts
import { t, tn } from "../../lib/i18n";

t("settings_title"); // "Settings"
t("keys_expires_on", { date: formatDate(d) }); // "$date$" placeholder
tn("history_entries", n); // picks history_entries_one / _other, supplies $count$
```

`t` is `chrome.i18n.getMessage` with named, typed substitutions. The
language is Chrome's UI language; there is no in-app switch. A key a locale
lacks falls back to `en` at the browser level.

Dates: `formatDate`, `formatDateShort`, `formatRelative` in `lib/i18n/format.ts`
(Intl-based, replaces date-fns `format`/`formatDistanceToNow` in UI text).

## Fragment format

```json
{
  "keys_expires_on": {
    "message": "Expires $date$",
    "description": "Key card footer. $date$ is a localised long date."
  },
  "history_entries_one": {
    "message": "$count$ entry",
    "description": "History header count"
  },
  "history_entries_other": {
    "message": "$count$ entries",
    "description": "History header count"
  }
}
```

- Keys: `<area>_<slug>` snake_case, one file per area (`settings.json`,
  `keys.json`, `workspace.json`, `onboarding.json`, `errors.json`, ...).
  Shared words live in `common.json` (`common_cancel`, `common_close`, ...).
- Placeholders: `$name$` lowercase inline. The build assigns `$1..$n`.
  Every locale must use the same set of placeholders as `en`.
- Plurals: `_one` / `_other` in `en`. Other locales add `_few`, `_many`,
  `_zero`, `_two` as their grammar needs, and MUST carry every category
  `en` has for that base.
- Every `en` entry needs a `description`: where it appears, what any
  placeholder holds, and length constraints. Translators (human or model)
  work from that alone.
- No em/en dashes in messages (repo rule). Use a hyphen.
- Keep markup out of messages. When a sentence contains a link or a bold
  span, split it into pieces (`..._before`, `..._link`, `..._after`) or use
  a placeholder the component fills.
- `extName` / `extDescription` in `listing.json` are the store listing and
  follow `scripts/check-locale-names.mjs`.

## Opting a literal out

```tsx
{/* i18n-ignore */}
<span>PGP Tools</span>
// i18n-ignore
<input placeholder="0xDEADBEEF" />
```

`/* i18n-ignore-file */` anywhere in a file skips it entirely (dev-only
surfaces). Brand names, fingerprints, armor headers, and code samples are
the legitimate uses.

## Adding a language

Copy `i18n/en/` to `i18n/<locale>/` (Chrome locale codes: `pt_BR`,
`zh_CN`, ...), translate the `message` values, keep `description` or drop
it, run `pnpm i18n:build`, then `pnpm i18n:check` for coverage and errors.
